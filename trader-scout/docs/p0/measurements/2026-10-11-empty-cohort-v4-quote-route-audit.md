# Base v4 quote-route follow-up

As of 2026-10-11, a bounded read-only follow-up tested whether 14 active Base Zora token-to-token v4 pools could be connected through their shared quote token `0x107fb51dbea200ae8e8d69ecf9afe13bfb6d3479` to an independently identified USD route. This is route evidence for selected observed peak events, not a lifetime ATH result.

## Findings

- The quote token has an observed v4 pool against official Base ZORA (`0x1111111111166b7fe7bd91427724b487980afc69`), pool ID `0x897c2d8a85e103e74de56663ea6edfc9e74c547c00c0900a8079ad990a432fcb`. Its Initialize record identifies dynamic fee marker `8388608`, tick spacing `200`, and hook `0x0469a4bd3724dc86c9542f4694c976da13c450c0`; the archived pool-swap query returned 808 events in the audited window. The official Zora support page identifies the Base ZORA contract: [Zora token contract addresses](https://support.zora.co/en/articles/5654721).
- The official Base Uniswap v3 factory (`0x33128a8fc17869897dce68ed026d694621f6fdfd`) returned three ZORA/WETH pools for fee tiers 500, 3000, and 10000. Their token identities, fee values, and deployed code were checked. At all 12 selected target blocks, the fee-500 pool had `liquidity() == 0`; it is not a usable price route despite its nonzero `slot0`. Fee-3000 and fee-10000 had nonzero historical liquidity at all 12 blocks. Their exact historical `slot0` values were read at each target block; same-block Swap searches returned no events in those three pools, so block-end `slot0` is a stable state observation for those particular blocks.
- For the 14 selected token events, the quote/ZORA leg was reconstructed by taking the latest archived quote-pool Swap strictly before each target event, ordered by block, transaction index, and log index. A two-call Base Multicall3 read at the frozen cutoff returned 18 decimals for each target token, the external quote token, ZORA, and WETH. Two public Coinbase ETH-USD 1-minute candle requests supplied the containing-minute low/high for these observations. These inputs yield provisional multi-hop **spot** USD compositions, retained with exact fractions and provenance in `event-ordered-pricing.json`.
- The resulting spot values diverge sharply from the same target Swap events’ amount-delta execution ratios: for the 13 October 9 events, the composed post-swap spot ranges are roughly `$82M–$422M` per token, while the composed execution ratios are around `$1.93e-11` per token. This is a major liquidity-depletion/spot-versus-execution anomaly and makes the spot values unsuitable as ATH candidates without protocol-level reconciliation. The September 25 row is also preserved separately. The earlier classification’s `raw_quote_atomic_per_raw_token_atomic` fractions match the event sqrt-derived atomic ratios exactly in all 14 sampled rows. One selected token (`0xe46504da7f7f9d9233d6118e27bdfbf27964a215`) has exactly one configured-pool Swap in the frozen annual scope, so its selected-pool maximum is that event. A separate source audit proves its 1 billion supply through this event; the configured-v4 scope still excludes other DEXes and does not establish all-market coverage. The bounded GeckoTerminal follow-up resolved the exact pool/token identity but returned no daily OHLCV candles, so this candidate still lacks the requested independent positive USD-high cross-check; see [the e465 check](2026-10-11-base-e465-gt-crosscheck.md).
- This still does not establish a price maximum across every target swap, complete coverage of all quote pools/migrations, or a suitable canonical ATH. The minute USD composition is a single centralized exchange’s candle range, not an exact synchronized executable quote. The route must preserve event ordering when quote/ZORA swaps share blocks with target token events. A follow-up checked historical liquidity and bounded recent Swap history in the two nonzero-liquidity ZORA/WETH v3 pools: fee-3000 has a Swap about two minutes before the Oct 9 observations, while fee-10000’s latest observed Swap is about 12 hours earlier. The fee-500 pool remains empty-liquidity. This supports fee-3000 as the more recent state route for those observations, but does not prove complete historical liquidity or USD-price coverage.

Uniswap documents the Base deployments and the v4 `StateView.getSlot0(bytes32)` read used for historical state: [Uniswap v4 deployments](https://developers.uniswap.org/docs/protocols/v4/deployments) and [StateView guide](https://developers.uniswap.org/docs/protocols/v4/guides/state-view). A nonzero spot price alone is insufficient; this audit checked historical active liquidity separately.

## Scope and provenance

The 14 events are the selected max-raw-spot observations from the frozen configured-v4 cohort audit, not all 1,194 observed swaps. The broader audit found 36 annual-active configured v4 pools and 42 cohort tokens with no observed swap in that configured-v4 scope; see [the frozen cohort scope audit](2026-10-11-empty-cohort-v4-scope-audit.md). Other DEXes, managers, and pool migrations remain outside that scope.

The read-only RPC evidence, parameters, response hashes, and raw bodies are in `.scout-data/diagnostics/empty-cohort-v4-quote-route-audit-2026-10-11/manifest.json` and its `raw/` directory. Decimal reads are in `decimals/manifest.json`; the keyless Coinbase candle responses and request metadata are in `coinbase-eth-usd-fx/`; derived event-order fractions and price-kind comparisons are in `event-ordered-pricing.json`. The follow-up used 116 logical Base RPC calls against a 120-call bound and two Coinbase GETs. No Codex, GeckoTerminal, Birdeye, Solana Tracker, or database writes were used.

**Conclusion:** the multi-hop route is now numerically reconstructed for 14 selected observations, but the pronounced spot/execution divergence is an unresolved quality gap. Do not promote these spot compositions as token ATH/FDV. The next necessary work is resolving the post-swap spot versus execution-price anomaly, proving token-specific supply for any FDV conversion, and searching the full eligible pool/trade scope before making any annual or all-time maximum claim.
