# ATH year-history options — 2026-10-13

This bounded follow-up checks options that could add history for the remaining unknown ATH records. The provider survey uses saved project evidence and first-party documentation; the Zora subsection also records seven bounded anonymous requests to its documented public service. No API keys, database reads/writes, or account setup were used. The note distinguishes a free public endpoint from a free account plan, and historical trades from candle highs or a canonical lifetime ATH.

### Anonymous Zora swap-history probe

The official [Zora coin-query docs](https://docs.zora.co/coins/sdk/queries/coin) describe `getCoinSwaps(address, chain, after, first)` and example fields `activityType`, `coinAmount`, `senderAddress`, and `blockTimestamp`. The [REST API docs](https://docs.zora.co/coins/sdk/public-rest-api) say REST paths map to SDK functions, recommend an API key to avoid high rate limiting, and do not publish an anonymous quota or retention guarantee.

I tested the documented function-name route against two frozen, source-matched Zora Base coins from the unknown ATH cohort, without credentials. A request to `/api/coinSwaps` returned HTTP 404 (`404 Not Found`, 13 bytes); the route at `/coinSwaps` returned HTTP 200. The working GETs used `address`, `chain=8453`, `first=100`; the API returned at most 20 edges for one token, so `first=100` is not evidence of a 100-row page limit.

Using quote amount × `priceUsdc` / (raw `coinAmount` ÷ 10¹⁸), one large event reconstructs to `$1.9816484e-11` per coin, 0.281% below Birdeye’s same-day high. Three rows produce extreme averages: two have microscopic `coinAmount`, and another full-supply-sized trade is still far above the Birdeye window. All were retained as anomalies, not filtered. |

This is a promising bounded cross-check, not a validated ATH: data is limited to Zora’s indexed coin swap activity, and the API does not promise that it spans all pools or migrations. |

The observed `currencyAmountWithPrice` object contains a quote-token address, quote `amountDecimal`, and `priceUsdc`; the official Zora query page lists swap amount and timestamp fields but does not define this field’s exact calculation, whether the quote price is historical-at-swap, or its rounding contract. The normalization above treats `priceUsdc` as the USD value of one quote-token unit and divides the resulting quote USD by the target coin quantity. For the older sample, its same-day maximum is close to the independent daily high. This supports that interpretation, but is not a substitute for the API’s full official field semantics or a same-transaction on-chain check. `amountDecimal` is emitted as a JSON number, so its source precision is provider-controlled; `coinAmount` is an integer string and target decimals (18) come from the source-matched local token proof. The official example exposes `coinAmount` but does not specify raw-versus-human units; the raw-unit interpretation here is inferred from the observed integer values and the verified 18-decimal token. These derived values are execution averages, not marginal spot prices or candle highs.

### Quote-price timestamp and supply check for 058e

All 92 returned swap edges use the same MATRY quote address (`0x364863eece7fd2e6c5f3dc13a3f043521f77ec49`). The response contains 91 distinct `priceUsdc` values, from `$0.0000027491069355` to `$0.0011560035896193`; the first day alone has 76 distinct values among 77 edges. On Sep 27, all five edge values differ (`$0.0010798363`–`$0.0011106285`), while the independently cached GeckoTerminal MATRY/WETH daily candle for that UTC day has a high of `$0.001120095946`. The edge-to-edge variation in one query response rules out a single constant quote price reused for all edges and is consistent with per-edge historical quote valuation. It does not prove that `priceUsdc` is timestamped at each swap; Zora’s published schema does not state that guarantee, and the daily candle comparison is not an exact-time match.

For the four UTC dates with returned events, every `priceUsdc` observation also falls inside the cached MATRY/WETH candle’s low-to-high USD range for that date:

| UTC date | Edges | `priceUsdc` min–max | Cached MATRY/WETH daily low–high |
|---|---:|---:|---:|
| 2026-09-24 | 77 | `$0.0000027491`–`$0.0011560036` | `$0.0000000003169`–`$0.0011649825` |
| 2026-09-25 | 9 | `$0.0002870272`–`$0.0011121439` | `$0.0000027519`–`$0.0011218357` |
| 2026-09-27 | 5 | `$0.0010798363`–`$0.0011106285` | `$0.0000000372809`–`$0.0011200959` |
| 2026-10-01 | 1 | `$0.0000224561` | `$0.0000057387`–`$0.0000937828` |

This date-level envelope match plus the large per-edge variation makes historical quote valuation more plausible than a single current-quote value, but the quote candle is daily and from an independent indexed pool; it cannot establish per-event timestamp semantics or exact price equality.

For the peak reconstructed edge (2026-09-27 16:58:43 UTC), the API reports 204.088445592385538139 DVA (`coinAmount` `204088445592385538139`) and quote-side amount `276.84873973895264` MATRY at `priceUsdc=0.0011106285156880768...`. With the independently verified DVA decimals of 18, this gives an execution-average price of `$0.001506582619/DVA`, 1.6653% above the Birdeye daily high; that falls inside the owner-accepted 2% comparison band, but remains an execution average and retains the quote-time caveat above.

The saved source/supply audit for this exact token records a 45-byte EIP-1167 runtime matching the verified Zora ContentCoin implementation, decimals `18`, current/pinned `totalSupply=1000000000000000000000000000` (1 billion units), a creation-block mint equal to that supply, and zero burn logs from token creation through the pinned audit block. The audit labels this historical supply as proven only through that anchor, not forever. Evidence is in `.scout-data/diagnostics/base-zora-ath-source-audit-2026-10-11/manifest.json` (entry `0x058e…c738`; source manifest SHA-256 `0cde638b069ed53f891caef21829d44c78788c2a15c46da52a119da84a3aac06`) and the unchanged Zora query responses/normalization cited above. This closes the exact token’s supply scale for the observed window; it does not establish all-market coverage or canonical lifetime ATH.

An offline check now links the largest API edge to its cached Base receipt. The successful receipt is in `base-zora-dva-matry-amm-pilot-2026-10-11/phase2-raw/02-candidate-receipt.json` (SHA-256 `dde1c8d37ebb3d2457305cd83646f92c36150fe7745ae619ca0994911b714f44`): transaction `0x5de8c05554f6c146f9e542587e2c125c8c4d666a1874dc354d34ca47c0d213dc`, block `0x3177730`, timestamp `2026-09-27T16:58:43Z`, status `0x1`. Its DVA/MATRY PoolManager `Swap` event for pool `0xe5e1121b233d89988ecd0b5b9312d8919b81a8efe4dbd9a8c8336ea324189c54` is at log index `0x99`; the cached Initialize record identifies currency0 as DVA and currency1 as MATRY. The event’s signed deltas decode to `+204088445592385538139` DVA raw and `-276848739738952660574` MATRY raw. Thus API `coinAmount` is confirmed as raw target units for this edge, and dividing by the source-verified 18 decimals yields the exact 204.088445592385538139 DVA. The phase1 pilot manifest (SHA-256 `02348d6691793103342cd7a915efe791497deafebafe00721e3ea7e056002ae6`) verifies MATRY decimals are 18; its exact quote delta is 276.848739738952660574 MATRY, versus API `amountDecimal` 276.84873973895264, a `2.0574e-14` MATRY difference consistent with the JSON-number precision limitation. Substituting the exact event quote amount changes the derived average only from `$0.0015065826190890420147` to `$0.0015065826190890421267` per DVA. This independently confirms both amount scales for the peak edge; it still does not establish the `priceUsdc` field’s exact timestamp semantics or prove that the indexed edge is the ATH.

For this same edge, the cached receipt also validates the two-pool route: 0.000115455870985401 WETH purchased the exact 276.848739738952660574 MATRY used in the DVA/MATRY swap. Applying the cached Coinbase ETH-USD minute low/high gives an independent realized route price of `$0.0015196742313`–`$0.0015199853745` per DVA. This is 0.869%–0.890% above the Zora-derived edge price, within the accepted 2% corroboration band. Birdeye’s same-day high is 1.665% below the Zora-derived value, also inside 2%, while it is 2.549%–2.570% below the route-derived value. Keep all three observed values and their price kinds distinct; the price-source candidate does not resolve Birdeye’s daily-high timing or the Zora endpoint’s partial history. The reproducible, non-database candidate certificate is `.scout-data/diagnostics/zora-058e-route-fx-candidate-2026-10-13/058e-candidate.json` (SHA-256 `941113c79a66900a52f079de7cdbcbd3638f2d4fba60c36858e24d8626778b56`); it leaves `ath_at` null and explicitly records that only 92 API rows were returned versus 326 swaps in the identified pool through the later pinned block.

The API is therefore a useful **candidate Zora-specific trade-history source**, and the 92-row cursor walk shows that a recent coin’s reported history can reach within minutes of its source-recorded creation. It is still not a validated ATH source. The endpoint’s response does not prove complete multi-pool or migrated-market coverage, and the 010e amount/value anomalies need handling grounded in exact transaction/quote data before adopting its extrema.

## Practical next tests

1. **Base/Zora subset:** the no-auth route and one complete 92-row cursor walk are verified. Next, reconcile every returned quote and target amount with the corresponding on-chain swap for one bounded coin; confirm the field semantics and quote-price timestamp, and check the USD execution maximum against all configured pools and the independent daily candle. Preserve dust-sized anomalies for transaction-level validation. Do not repeat the `/api/coinSwaps` 404 path.
2. **Base/Clanker subset:** do not spend requests on Clanker `/marketcap` for ATH work. Its documented route is a current value. Continue with the existing saved pool/Swap evidence for the four remaining high-holder Base candidates.
3. **DexPaprika:** reserve Free only for metadata/short recent windows. A full 365-day scan would require a plan with historical OHLCV entitlement; the listed free tier cannot fill the annual baseline.
4. **RH/Solana:** none of these new launchpad routes closes the current gaps. The saved analysis still shows 30 RH candidates with unknown holders and empty current provider windows, and three Solana records with unknown holders. Preserve the holder gate; price evidence alone does not make them current runner candidates.

The next meaningful broad coverage gain remains **locally retained forward history** from launch/pool creation for eligible tokens, plus bounded historical replay for specific gaps where a trusted archive source is available. A 7-day or current-value endpoint can help verify identity/current state, but cannot backfill prices that were never retained. Keep Codex as its own historical observation, and store any new provider-window maximum with its exact source/window/scope and `ath_at` unknown unless lifetime coverage is independently established.
