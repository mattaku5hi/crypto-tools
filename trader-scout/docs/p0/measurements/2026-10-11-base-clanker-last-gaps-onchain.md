# Base Clanker remaining page-1 pool price audit

Read-only audit of the seven remaining candidates in the captured Base Clanker 53-token cohort. The source-supply audit fixes each token at 100,000,000,000 units and 18 decimals. This audit compares each token’s cached GeckoTerminal (GT) global maximum within captured page-1 pool histories against the highest decoded USDC execution ratio across every captured whole-range Swap log in the known page-1 USDC pools. The true USDC-scope maximum must land on the GT maximum’s own UTC day; no event is selected by date to improve the comparison. It does not alter any FDV record.

## Method and scope

The audit confirmed Base chain ID `0x2105` and anchor `0x3206b2c` / `0x021113f4f7d0a2fe23e0036948b341ef7bbe5c75a604eb56f96c8a873d5e39b8`. It issued 57 RPC calls: 2 preflight, 17 per-pool Initialize lookups, 17 whole-range Swap queries, and 21 peak-proof checks. All 17 Swap responses were complete and below the 5,000-log limit; they returned 520 logs total. No ranges were split and no calls retried. No public FX requests were needed; dated Kraken USDC/USD daily candles were already cached.

The existing `scout-dex-evm` v4 Initialize and Swap decoders were used. Swap ratios use the v4 signed `amount0`/`amount1` deltas; same-sign, zero, or token/quote-inconsistent events are excluded. Token decimals are 18 from the cohort source audit. USDC decimals were queried at each selected historical peak block and returned 6. For each token, the all-history maximum valid USDC execution ratio is computed across every Swap log in every captured page-1 USDC pool. It must fall on the GT global-maximum UTC day; only then is that same event’s ratio converted using Kraken USDC/USD low and high for its actual UTC date. Kraken daily tuple fields are `high=row[2]` and `low=row[3]`; `close=row[4]` is not used as the low.
