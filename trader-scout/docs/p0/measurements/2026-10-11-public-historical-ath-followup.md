# Дополнение: бесплатные публичные источники исторического ATH — 2026-10-11

## Вывод для следующего PoC

**DexPaprika заслуживает отдельной проверки в качестве прямого ATH reference для Base и остальных трёх сетей.** На 11 октября 2026 публичный endpoint `GET /networks/{network}/tokens/{address}` без ключа вернул `price_stats.ath` и `price_stats.ath_date` для выбранных Base, Solana, BSC и Robinhood Chain токенов. Base и Solana ответы содержали даты ATH старше 180 дней. Это именно поле, которого не было в проверенной ранее token-latest OpenAPI-схеме. Документированный бесплатный план разрешает token endpoints и все четыре сети, но бесплатный pool OHLCV ограничен 7 днями, а token OHLCV недоступен; следовательно, endpoint — полезный direct-ATH lookup, не бесплатный источник свечной реконструкции.

Эти ответы не подтверждают coverage произвольного адреса, всех токенов, всех пулов или всей жизни токена. Не выяснено, как `price_stats.ath` агрегирует рынки, обрабатывает миграции и исключает ошибочные/тонкие пулы. В одном Base примере текущая страница прямо помечает экстремальное расхождение цен в пулах; прямое поле нельзя автоматически считать корректным ATH без sanity checks.

## DexPaprika: живые ответы показывают ATH в публичном token endpoint

Первичная pricing page относит token endpoints к Free, указывает 100K credits за rolling 30 дней, 30 запросов в минуту, 36 сетей и задержку данных до 60 секунд. Она отдельно ограничивает бесплатную историю: pool OHLCV — 7 дней и свечи от 10 минут; token OHLCV доступен только на Pro. Документация отмечает, что keyless режим работает для локальных проб, но free key даёт отдельную квоту. [DexPaprika pricing](https://dexpaprika.com/api/pricing), [token endpoint reference](https://docs.dexpaprika.com/api-reference/tokens/get-a-tokens-latest-data), [supported chains](https://docs.dexpaprika.com/resources/networks).

The observed values do not establish a stable provider contract: `price_stats` is visible in public responses but missing from the previously inspected latest-token schema. Confirm field shape and failure/null behavior before writing an adapter. The response has no quote-currency or source-pool field; `ath` appears to be USD token price by context (`summary.price_usd` and matching page display), but no authoritative field-level definition or quote-source aggregation policy was found in the docs. Do not interpret it as ATH FDV or derive FDV from current supply.

## CoinMarketCap: documented keyless route conflicts with live plan gate

The official K-line reference says `/public-api/v1/k-line/candles` can be called without an API key and that the response includes each candle's `high`. One recent Base WETH daily-candle request on 2026-10-11 returned HTTP 403 with JSON `error_code: 1013`, `error_message: "Your API Key subscription plan doesn't support historical data access for Dex API."` The report's earlier old-Base request was also 403, without a captured body. The request yielded no candle, and its end time was future-relative; it does not count as a successful recent-candle probe. The failures establish a historical DEX API plan gate, not retention. Do not retry 403 or treat this route as a usable keyless fallback on current evidence. CMC's general troubleshooting page documents 1005/1006 key errors but does not list 1013, so its exact plan semantics are inferred only from the response text. [K-line reference (keyless claim and candle `high`)](https://coinmarketcap.com/api/documentation/pro-api-reference/ohlcv/), [Keyless Public API guide](https://coinmarketcap.com/api/documentation/pro-api-reference/keyless-public-api), [error-code reference](https://coinmarketcap.com/api/documentation/guides/errors-and-rate-limits), [recent Base WETH request](https://pro-api.coinmarketcap.com/public-api/v1/k-line/candles?platform=199&address=0x4200000000000000000000000000000000000006&interval=1d&from=1791676800&to=1791763200&unit=usd&limit=1&pm=p).

Separate from DEX K-lines, a CoinMarketCap tutorial updated 2026-08-04 documents `/v2/cryptocurrency/price-performance-stats/latest` as available on every plan including Basic, returning `all_time.high` and `high_timestamp`. It requires a CMC cryptocurrency ID and is a listed-coin performance endpoint, not an arbitrary DEX contract-address API. This is an additional cross-check for mapped/listed assets only; it does not establish all-chain token coverage. [CMC tutorial and endpoint semantics](https://coinmarketcap.com/api/resources/how-to-retrieve-price-performance-stats-roi-ath-atl/), [v2 Price Performance Stats reference](https://coinmarketcap.com/api/documentation/pro-api-reference/cryptocurrency).

## Coinranking: useful indexed-coin ATH cross-check, selective address coverage

Official Coinranking docs define `allTimeHigh.price` and timestamp, allow `contractAddresses[]` as a `/coins` filter, and list the `/coins`/coin-details price APIs on the free plan. Free is 5,000 calls/month with one API key, 100 records per request, and tier 3 excluded. This is a low-cost reference for tokens Coinranking has indexed; it is not evidence of arbitrary long-tail DEX token coverage, and the ATH comes from Coinranking's coin markets rather than a demonstrated all-pool on-chain price source. [Coinranking free crypto price API and plans](https://coinranking.com/api/features/crypto-price-api), [contract-address and ATH fields](https://coinranking.com/api/documentation/coins/coins), [coin detail ATH semantics](https://coinranking.com/api/documentation/coins/coin-details).

Two bounded no-auth GETs were made on 2026-10-11 using the documented `contractAddresses[]` query syntax. Querying Base WETH `0x4200000000000000000000000000000000000006` returned HTTP 200 with zero matched coins. A single query for Base USDC, BSC USDT and Solana USDC returned one USDC coin whose listed contract-address array contains the requested Solana USDC address; it did not return a Base or BSC match. The response exposes `allTimeHigh` for that indexed USDC coin. Because official setup examples require `x-access-token`, this no-auth behavior is a probe only; it does not establish supported keyless access or coverage. The listed `contractAddresses` array must be checked against network-qualified `blockchain/address` identities rather than merging same-address or same-symbol assets.

Exact query URLs: [Base WETH lookup](https://api.coinranking.com/v2/coins?contractAddresses%5B%5D=0x4200000000000000000000000000000000000006); [Base USDC + BSC USDT + Solana USDC lookup](https://api.coinranking.com/v2/coins?contractAddresses%5B%5D=0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913&contractAddresses%5B%5D=0x55d398326f99059fF775485246999027B3197955&contractAddresses%5B%5D=EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v).

## Что можно делать дальше

1. Добавить ограниченный DexPaprika lookup PoC в набор заранее выбранных Base addresses; compare returned ATH against Codex's existing per-token records and one independently inspected pool candle/trade history. Keep provider price ATH separate from ATH FDV.
2. Include Solana, BSC and Robinhood samples in the same small validation set. Record exact chain, token, returned date/value, pool counts, API errors, and whether the ATH is plausible against visible pool history. Treat `null`, missing token, and suspicious extreme values as coverage/quality outcomes, not zero.
3. Check the undocumented `price_stats` response against the first-party token page and token-specific pools. The page demonstrates the value reaches a public surface; it does not prove index completeness, cross-pool aggregation semantics, or historical token price accuracy.
4. Keep Coinranking as an optional cross-check after obtaining a user-managed free API key and validating exact network-qualified contract matching; do not build all-address ingestion around a coin listing API.

## Проверки и границы

- Nine direct provider API GETs plus one DexPaprika HTML page GET were made: six DexPaprika token JSON responses across four target networks, two Coinranking address-filter responses, and one CMC candle request. All had 15s timeout and response caps at 2 MiB; no API credentials/accounts were used, and no 403 was retried. The CMC request was rejected; other provider API requests returned 200. Separate CMC docs research did not call its API.
- Official docs/pricing pages and first-party indexed token pages were used; live chain data was not independently recomputed. No project code, database, configuration, existing report, or production API was changed.
- Open questions: documented semantics and history window of `price_stats.ath`; pool selection and migration behavior; coverage for arbitrary/missing tokens; field stability/versioning and null behavior; whether all ATH values are token price in USD and how suspicious outliers can be independently rejected.

The API payloads include `price_stats`, `summary.price_usd`, `summary.fdv`, current `total_supply`, `decimals`, `added_at`, and `last_updated`. They have no ATH currency tag, source pool/pair ID, historic supply, tracking-start guarantee, or aggregation/migration provenance. The Codex anchors are ATH FDV while the provider exposes an undocumented price-like ATH; they are not semantically equivalent. Their disagreement under even the provisional present-supply calculation is evidence against writing the provider field into the Codex ATH FDV column. Anchor metadata comes from the read-only `.scout-data/diagnostics/base-ath-coverage-2026-10-11.json` snapshot.

The first-party token-latest endpoint contract and OpenAPI source omit `price_stats.ath` / `ath_date` ([endpoint reference](https://docs.dexpaprika.com/api-reference/tokens/get-a-tokens-latest-data), [OpenAPI source](https://github.com/coinpaprika/skills/blob/main/dexpaprika-api/references/openapi.yml)). Their runtime presence is useful for exploratory triage but is not a documented compatibility contract. `added_at` is provider index time, not proof that history starts at token creation. Free pool OHLCV is only seven recent days and token-level OHLCV is a paid Dev/Pro feature, so keyless/Free users cannot independently rebuild full history from documented DexPaprika candles ([pricing](https://dexpaprika.com/api/pricing), [first-party API skill](https://github.com/coinpaprika/skills/blob/main/dexpaprika-api/SKILL.md)).

The final RH probe returned headers `x-api-plan: keyless`, `x-credits-limit: 10000`, `x-credits-remaining: 9980`; no credentials were sent. Pricing distinguishes the lower keyless request limit from the Free-key allowance. The first-party [API terms](https://dexpaprika.com/api/terms) describe Free use for developing/testing/supporting Apps and reserve commercial use to non-Free plans; this blocks production adoption for a commercial product absent another applicable license.

They return non-null `price_stats.ath` values but were not matched to local Codex anchors in this follow-up. Thus cross-chain response presence is demonstrated; cross-chain accuracy is not.

The initial sequence also attempted the Solana address `DezXAZ8z7PnrnRJjz3wXBoRgixCaAnD1vQ4b8Zp3n`, whose response was not preserved; its request outcome is uncertain. Eight successful JSON responses are archived, and that additional attempted GET means the cap may have been exceeded by one. This was an execution error; no further provider calls were made once the ambiguity was identified. The intended two-per-network Codex-anchor comparison is incomplete outside Base. This section does not claim eight-call all-chain accuracy validation.

**Decision:** DexPaprika remains a useful no-key four-chain *candidate price-ATH hint* for manual triage, including old Base Zora tokens. This evidence does not justify a production adapter or persistence to Codex ATH FDV: the field contract/currency is undocumented, pool and historic-supply semantics are missing, both matched Base cases disagree materially, prior samples show outlier risk, and Free commercial-use restrictions apply. Reconsider only after provider confirmation of semantics/licensing and a broader representative comparison establishes acceptable coverage and error bounds; retain a distinct provenance and unknown status meanwhile.
