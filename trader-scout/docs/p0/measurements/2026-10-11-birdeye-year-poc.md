# Birdeye daily OHLCV year-window PoC — 2026-10-11

## Result

Birdeye accepted the locally supplied key on the documented token-level OHLCV V3 route for five valid token/network requests: two Base Zora tokens, one Solana token, one BSC token, and one Robinhood token. A sixth request returned HTTP 400 because the candidate Solana address was invalid; that address was not retried. The key was read from local configuration in process memory, never printed, put in a URL, or saved. The response archive was scanned for the key string and none was found.

The requested range from 2025-10-10 to request time on 2026-10-11 (slightly more than 366 days) is available through the documented route, but this does not establish one year of usable observations for each token. Results are sparse daily candles (`padding=false`) and the endpoint's docs explain that empty candles are omitted. The provider does not document the 1D retention boundary, token-level pool aggregation, or migration history. Missing dates therefore remain unknown: this test cannot distinguish no-trade days from coverage gaps or candles excluded by `outlier=false`.

## Same-unit price and outlier quality follow-up

The Codex snapshot includes `extrema.athPrice`, so the comparison below is USD per token against Birdeye's USD-per-token daily highs. These are same-unit comparisons, not an FDV conversion. Across all five tokens, Birdeye's `outlier=false` window high divided by Codex ATH price was: Base a187 `9.6465x`, Base 5a0 `4.6078x`, Solana Foia `0.03248x`, BSC 06ac `0.03733x`, and Robinhood fa89 `0.002936x`. Their extrema timestamps need not match; the series have different, undocumented market/index scopes.

Three bounded follow-up calls repeated the same 1D USD date ranges and toggled only `outlier=true` for RH fa89 and BSC 06ac; a third, Base a187, timed out after the 25-second read timeout and was not retried. RH returned 37 dates in the same range; its max rose from `0.0002347258972858377` (Sep 7) to `0.0003241733339566428` (Sep 7). On the Codex ATH date, Sep 4, its high changed from `1.9400839620415374e-20` to `8.200605879384362e-20`, still far below Codex's `0.0799580409` same-unit ATH price. BSC returned the same 77 date labels; max rose from `0.0037143220262524793` (Mar 1) to `0.0050213037524690874` (Mar 2), still far below Codex's `0.0995042861`. The BSC Codex ATH date, May 5, remained absent in both responses. Outlier inclusion alone therefore does not explain the large differences. The provider does not document the outlier algorithm; Base was still unknown at this step after the timeout, before the separate successful follow-up below.

A fourth bounded request used `chart_type=mcap` for the Solana Foia token. It returned two dates and a maximum chart value of `12538.413222854837` on Sep 30. Birdeye documents `mcap` as a Solana token-chart mode and says it falls back to price when supply is unavailable; it does not publish a historical-supply formula in this endpoint reference. As a diagnostic only, multiplying the prior price-chart high `0.000012626106426182473` by the Codex snapshot's current supply `993054608.52865` gives `12538.41317429370782368694835`, close to this chart value. That does not establish Birdeye's historical supply basis or make its value a validated FDV. The mcap chart remains only about `3.248%` of Codex's ATH FDV `$386031`, consistent with the same price-series gap when using this current supply snapshot.

The toggle comparison changes some daily highs while leaving returned date counts and date labels unchanged for RH/BSC. This says only that the provider's inclusion switch affected values in these samples; it does not identify which pools or swaps contributed. Birdeye's token-level OHLCV route is distinct from its pair-level route, which its docs describe as one venue/pair rather than token-level aggregation ([pair OHLCV reference](https://data.birdeye.so/docs/data-api/price-ohlcv/get-defi-v3-ohlcv-pair)). The same token endpoint documents `chart_type=price|mcap`, Solana-only mcap mode, and its supply-unavailable fallback ([token OHLCV reference](https://data.birdeye.so/docs/data-api/price-ohlcv/get-defi-v3-ohlcv)). No request here isolated pools, launchpad/bonding-curve phases, migration continuity, per-token index start, or historical supply. We therefore cannot attribute the discrepancies to lifecycle/pool coverage, and sparse no-padding dates remain ambiguous rather than proven missing history.



## Final outlier-toggle checks

Two final authorized token-level requests used `outlier=true`. Solana repeated its exactly saved original parameters except this toggle. The first Base probe did not retain its precise request parameters/time_to, so the later Base bound `1791681286` cannot be certified as identical to that initial query; returned date labels/counts were unchanged. The separate Base follow-up returned HTTP 200 after the earlier timeout; the Solana request tested whether filtering hid its Codex ATH-day spike. Both returned the same date labels/counts as their prior `outlier=false` response (Base 55, Solana 2). On Base a187, the May 8 candle high was unchanged at `0.0000039071110134015235`, about `1.0273x` Codex's `0.0000038031` ATH price. The window maximum increased from `0.00003668655655319179` to `0.00005642741802520651` on launch day, so the window-max disagreement remains and outlier inclusion does not validate that high.

On Solana Foia, the Sep 30 daily high changed from `0.000012626106426182473` with `outlier=false` to `0.00039030368965734766` with `outlier=true`. The latter is about `1.0040x` Codex's `0.0003887305` ATH price on the same UTC day. Thus the default false filter did suppress a same-day extreme in this sample, and inclusion makes the token-level price history consistent with Codex's observed ATH price. This is strong cross-source corroboration, not proof that the underlying trades are valid or that provider ATH completeness is guaranteed. The response's volume and `v_usd` fields do not establish the price unit or outlier algorithm; no additional inferences are made from them.

## Contract and remaining unknowns

Birdeye documents `GET /defi/v3/ohlcv`, required `X-API-KEY`, `x-chain`, token `address`, intervals including `1D`, Unix-second `time_from`/`time_to`, `currency=usd`, range mode, a 5,000-record maximum, no empty candles when `padding=false`, and provider outlier filtering when `outlier=false`. The published CU schedule charges 25 CU for up to 100 returned items. The docs list `base`, `solana`, `bsc`, and `robinhood` for `x-chain`. [Birdeye OHLCV V3 reference](https://data.birdeye.so/docs/data-api/price-ohlcv/get-defi-v3-ohlcv), [pricing and plan limits](https://data.birdeye.so/docs/guides/payment/pricing), [supported networks](https://data.birdeye.so/docs/resources/data-coverage/supported-networks).

The five HTTP 200s establish access using this supplied key for those token/network requests as of 2026-10-11; they do not by themselves prove the key's plan name, stable entitlement, or free-plan quota outside these calls. Birdeye explicitly documents short retention for `1s`, `15s`, and `30s` data but does not state a daily-history maximum on this endpoint. Unknowns also include per-token tracking start, pool aggregation, migration continuity, completeness on no-bar dates, the reason for the near-zero RH observation, and historical supply needed to relate price ATH to Codex ATH FDV.

**Decision:** Birdeye is an actionable key-authenticated daily OHLCV source for the tested chains; a key was supplied locally, but its account plan and ongoing entitlement were not independently verified. Same-unit checks now show large, bidirectional ATH price disagreements on all five samples, and the tested outlier toggle does not explain them. Keep its series and provenance separate; the evidence does not support writing provider maxima into Codex ATH price/FDV or claiming complete yearly ATHs. Pool/indexing/lifecycle coverage and supply policy still need validation.
