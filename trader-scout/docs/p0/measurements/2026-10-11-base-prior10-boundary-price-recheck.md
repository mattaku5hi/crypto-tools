# Base Clanker prior-10 Q192 boundary-price recheck — 2026-10-11

This read-only follow-up compares exact Uniswap V4 post-swap marginal prices from cached `Swap.sqrtPriceX96` with execution-average ratios from those same swaps. The focused question was whether the `0x92d958…` execution maximum, about 1.77% above the cached same-day GeckoTerminal high, could still have a marginal spot matching the market-provider window high. No database or application code was changed.

The anchor remains Base block 52,456,236, hash `0x021113f4f7d0a2fe23e0036948b341ef7bbe5c75a604eb56f96c8a873d5e39b8`. This reuses the source-verified, constant-supply records and pool identity/log scans from the [prior-ten onchain audit](2026-10-11-base-clanker-prior10-onchain.md) and its [native-pool and date follow-up](2026-10-11-base-clanker-prior10-followup.md). Those reports prove 100B supply for their selected cohort; this price-only pass does not re-establish that supply evidence.

## Method and evidence scope

The [V4 `IPoolManager` event definition](https://github.com/Uniswap/v4-core/blob/main/src/interfaces/IPoolManager.sol) defines the emitted `sqrtPriceX96` as the pool's price after the core swap. The [PoolManager implementation](https://github.com/Uniswap/v4-core/blob/main/src/PoolManager.sol) emits `Swap` before the `afterSwap` hook runs. I therefore treat `sqrtPriceX96` as the core post-swap marginal state, not as an execution average, final hook-adjusted wallet price, or guaranteed price for a trade size.

For each event, the exact marginal quote/token fraction is computed from `sqrtPriceX96² / 2^192`, inverted according to the Initialize-verified `currency0`/`currency1` ordering, then scaled by `10^12` for an 18-decimal candidate token against 6-decimal USDC. The execution average is the absolute signed int128 quote delta divided by the absolute token delta with the same decimal scale. The raw integer fractions are preserved; decimal values below are display-only.

For `0x92d958…`, the cached scan already covered seven USDC pools. One additional full-range PoolManager log request covered its eighth initialized pool, a native-ETH pair, from its Initialize block through the same anchor. The response contains ten swaps; all eight indexed pools now have captured logs through the anchor, including three USDC pools with zero logs. Kraken's cached ETH/USD day candle bounds that pool's displayed USD prices. This closes the known indexed-V4-pool log gap for this candidate; it does not establish coverage of every Base DEX or every possible pool.

The other four candidates reuse previously captured indexed-pool scans. Quote-token pools are not converted to USD unless their quote identity and dated USD route are established; in particular, the ZORA-quote pool for `0x00b0a0…` remains unconverted. The pool listing is not asserted to be a complete market-wide pair index.

## Conclusion

For `0x92d958…`, the post-swap marginal spot on the same pool and same event as the largest USDC execution average is a plausible explanation for why the execution ratio misses the cached GT high while the spot ratio matches it. This is a meaningful price-kind distinction, not a correction to the event amounts. Yet the highest captured post-swap spot in another indexed USDC pool is higher than both provider highs. Without an adopted rule for selecting or excluding such pool states, the evidence supports neither a canonical market-wide ATH nor a FDV write.

The other four candidates likewise show that execution-average and post-swap marginal prices can diverge in either direction. A same-day, same-pool marginal match is not enough when another known pool/event has a higher value or the date differs. These are observed V4 boundaries only through the pinned anchor; non-V4 factories, incomplete external pool discovery, later migrations, unverified quote routes, and post-hook accounting remain outside the proven scope. The existing date/1% gates and price policy were not changed.
