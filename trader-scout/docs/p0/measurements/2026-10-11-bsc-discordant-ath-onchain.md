# BSC discordant ATH price audit: bounded on-chain corroboration

Captured 2026-10-11 UTC. Scope: the four entries in `crosscheck_discordant` from the GeckoTerminal cross-check manifest. This is price-source corroboration only; it does not establish lifetime ATH or trader PnL. The companion supply audit separately proves fixed 1,000,000,000 supply / 18 decimals / one creation mint and zero burns for this cohort.

## Procedure

- Read-only BSC RPC. Endpoint was read privately from `SCOUT_BSC_RPC_URL`; URL and credentials were not written to output. RPC chain ID returned `0x38` (56). The first pass used 30 RPC calls. A bounded WBNB follow-up used 7 RPC calls (limit 8) for anchor verification, peak block timestamps, and receipts. A separate FD74 conversion follow-up used 2 calls (one block timestamp and its receipt). Raw request parameters, HTTP status, Date header, response byte count, SHA-256, and response bodies are archived under `raw/`, `followup/raw/`, and `followup-usd1/raw/`; the endpoint itself is intentionally redacted. Four initial `eth_getLogs` calls used an end block above the RPC head, returned JSON-RPC `-32602`, and were followed by one corrected whole-range query per pool; no automatic retry, range chunking, or continuation was used.
- Cached GeckoTerminal pool identities were used only to identify candidate contracts. Each pool returned expected `token0`, `token1`, `factory`; its pinned factory `getPair`/`getPool` returned the exact pool address. Deployment families are the existing FixtureVerified PancakeSwap v2/v3 entries in `crates/scout-dex-evm/src/gate.rs`. First three use WBNB; the fourth uses USD1. The event topic and ABI layout were checked against the existing decoder constants in `crates/scout-dex-evm/src/v2_swap.rs` and `pancake.rs`.
- `eth_getLogs` covered each pool from its migration block through BSC block 126,987,545. The successful primary RPC header query returned the exact expected anchor hash `0x9558e75a5fcfbb3164a83035430d99d2e691e703f12b728271863d460b30f7df`, verifying the corrected log range reached the requested anchor. Results were 166, 175, 220, and 186 logs; each is below the 5,000-log cap and the full raw response is retained. Swaps were treated as pool-side exchanged amounts only; no trader address was inferred. Each pool’s strongest quote/token ratio is reported in `raw/rpc-derived.json`.
- Public FX: KuCoin BNB-USDT 1-minute candles, exactly 1,440 candles/day, plus Kraken USDT/USD 1-day OHLC; independent product metadata verified both symbols. The exact KuCoin minute low/high is multiplied by that UTC day’s Kraken USDT/USD low/high, without assuming USDT=1 USD. Initial public FX request count: 8. The FD74-only follow-up used 3 additional public GETs (KuCoin USD1 currency identity, USD1-USDT product metadata, and its exact 1-minute candle); it reused the already archived Kraken USDT/USD daily candle. Each request used a 25 s timeout, 2 MiB body cap, no auth, automatic retries, or key rotation.
- For the three WBNB pools, follow-up block queries fetched the exact timestamps of the max-ratio swaps. Each successful receipt has status `0x1`, the expected transaction/block/hash, and exactly one log at the expected pool address and log index. Each timestamp selects a minute already present in the archived 1,440-row KuCoin BNB-USDT candle set. USD intervals below multiply that minute’s BNB low/high by the cached Kraken USDT/USD day low/high; the interval handles the second-resolution gap inside each minute without assuming USDT parity.

## Quote-source verification

WBNB’s single Sourcify v2 request returned a verified `WBNB.sol` runtime match and `proxyResolution.isProxy=false`. The verified source credits `balanceOf[msg.sender]` by exactly `msg.value` in `deposit()` and returns exactly `wad` native currency in `withdraw(wad)`. One `eth_getCode` at the verified BSC anchor was byte-for-byte equal to Sourcify’s on-chain runtime. This supports using WBNB as 1:1 native BNB for these event ratios.

USD1’s Sourcify v2 request returned an exact runtime match for an EIP-1967 proxy, with implementation pointer `0x694Aa534bdef8eD63244eB902E7914e527891F08` named `StablecoinV2`; only the proxy’s source files were returned in this bounded request. A historical `decimals()` call at the peak event block returned 18. KuCoin currency metadata identifies the BSC USD1 contract as `0x8d0d000ee44948fc98c9b98a4fa4921476f08b0d`, matching pool token0, and lists deposits and withdrawals as enabled. KuCoin product metadata lists USD1-USDT trading as enabled; its exact 2026-01-21 17:31 UTC candle is 0.9997 USDT/USD1. Multiplying this by the cached 2026-01-21 Kraken USDT/USD daily low/high (0.99700–0.99927) gives a dated cross-venue USD range. This uses observed market rates, not a fixed peg.

For `fd74…4444`, the pool quote is USD1 (`0x8d0d…8b0d`), token0. The cached Pancake v3 event was re-decoded with `scout_dex_evm::decode_pancake_v3_swap`, which reads the first two of seven data words as signed `amount0` and `amount1`. The max event is at block 76,604,190, log `0x213`, tx `0x87d6a88f08ae5097301fb030267b9a7223a071592afe9c00937b6d5a7913e577`: `amount0=1,708,178,239,801,737,790,184` USD1 raw; `amount1=−16,920,082,434,303,050,871,644,513` token raw. A historical-block `decimals()` call returned 18 for USD1, so the exact event ratio is `0.0001009556688883885308102701063 USD1/token`. Its block timestamp is 2026-01-21 17:31:50Z and the transaction receipt has status `0x1`; the receipt contains exactly one log at the expected pool and log index `0x213`, with the same block hash as the block response. Using the closed daily FX method of ADR-021 amendment 14, the KuCoin daily USD1-USDT low/high (0.9995/1.0002; positive volume and turnover) and same-day Kraken USDT/USD low/high produce `$0.0001006024754807825035352303764–$0.0001009021476443500271842151649` per token. The full daily envelope lies 0.046–0.343% below Birdeye and 11.805–12.138% above GT; this supports Birdeye’s same-day numeric high under the existing 1% daily-FX threshold. It is dated daily cross-source sensitivity, not an instantaneous or executable event-time price. Preserve the separate minute-level gap: exact 17:31 candle has zero volume/turnover and is excluded; populated 17:27 and 17:38 candles do not bracket the event within five minutes on both sides. No peg is assumed.

The earlier draft’s purported `424205.216…` ratio and amounts `2105856…/4964…` are preserved as a superseded diagnostic and excluded: they do not match the protocol-decoded `amount0`/`amount1` words. See `followup/superseded-fd74-decode-diagnostic.json`.
