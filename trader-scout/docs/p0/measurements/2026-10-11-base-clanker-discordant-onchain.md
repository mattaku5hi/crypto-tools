# Base Clanker discordant-price audit — bounded v4 swap corroboration

Captured 2026-10-11 UTC. This read-only audit follows the cached GeckoTerminal/Birdeye cross-check for 53 additional Base Clanker tokens. Their fixed supply of 100,000,000,000 tokens at 18 decimals is separately established through Base anchor block 52,456,236, hash `0x021113f4f7d0a2fe23e0036948b341ef7bbe5c75a604eb56f96c8a873d5e39b8`; see [the supply audit](2026-10-11-base-additional-clanker-supply.md).

## Scope and method

The composed provider pass and pool-scope completion left 15 tokens unresolved after 38 of 53 were aligned. The initial selection was `6bb636…`, `cddbce…`, `374d69…`, and `021b78…`; ranking review found it had omitted eligible cached page-1 USDC v4 pools for `f3ad70…`. I scanned both `f3ad70…` pools and retained `021b78…` as an additional screened case. The four primary cases are `6bb636…`, `cddbce…`, `374d69…`, and `f3ad70…`. The full 15-token ranking, selection correction, and exclusions are preserved in the private analysis artifact.

I used the existing registry-gated Base Uniswap v4 PoolManager at `0x498581ff718922c3f8e6a244956af099b2652b2b`. The Base RPC returned chain ID `0x2105` and the expected anchor hash above. For each token, both pools from its cached page-1 listing were checked with `Initialize` logs and scanned for `Swap` logs from initialization through the anchor. All ten Initialize records decoded to the expected token/USDC currency pair and indexed pool ID. The ten full-range Swap queries returned 296 logs total (3–59 per pool), each under the 5,000-log cap. The existing `scout-dex-evm::decode_v4_initialize` and `decode_v4_swap` SDK decoders were used; accepted amounts are nonzero, opposite-signed pool execution deltas, with quote amounts converted using 6 USDC decimals and token amounts using 18. No trader identity is inferred.

For each candidate’s maximum ratio across both scanned pools, I fetched the exact block header and transaction receipt. All five receipts succeeded and contained the expected PoolManager/pool ID/log identity; each receipt block hash matched the separately fetched block header and scanned log. The USD interval multiplies the exact event ratio by the cached Kraken USDC/USD daily low/high for that same UTC date. This is the existing daily stablecoin-FX sensitivity method in ADR-021 amendment 14: an exchange-observed interval, not a fixed peg or global FX bound. No public FX request was needed. Historical `eth_call` requests for USDC `decimals()` (`0x313ce567`) at each of the five peak blocks returned `6`; per-call parameters, statuses, response hashes, and raw files are indexed in the manifest.
