The saved Base V4 pool scan identifies the quote address in pool `0xc8a194…d6271d` as the ZORA contract `0x1111111111166b7fe7bd91427724b487980afc69`. Its maximum observed execution ratio is `0.001745473992445937023612196182 ZORA/token` at `2026-05-02 02:52:21 UTC` (transaction `0x045a30…10407f`, block 45,450,497). This is a quote-unit execution ratio, not a USD price.

Coinbase’s public Exchange API returned HTTP 200 for product `ZORA-USD` and reported the market online. A request for the exact one-minute candle containing the event returned `[]`. Coinbase documents that historical candle intervals with no ticks are omitted, so this result means there is no candle observation for that minute; it does not justify carrying a nearby rate into the event. The Coinbase candle schema is `[time, low, high, open, close]`, with an explicit 300-candle request cap. See [Coinbase Get product candles](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles).

The original GeckoTerminal token-pool-list request raised `HTTPError`, but that exception’s status/body was not retained. It was not retried. Both contracts use 18 decimals in the saved pool evidence, yielding the `0.001745473992445937… ZORA/token` execution ratio above. The receipt verifies this on-chain observation but does not provide quote/USD conversion. The raw receipt and hash are preserved in `.scout-data/diagnostics/base-00b0-zora-quote-history-2026-10-13/manifest.json`.

This ZORA event alone would need a same-minute ZORA/USD value of approximately `$0.0128948` to match the already observed USDC-pool execution maximum, or `$0.00573514` to match Birdeye’s saved same-day high. Thus, even a successful conversion of this one ZORA event would not establish the token’s maximum across all known pools. The known USDC post-swap spot maximum is a third price kind and remains separate.
