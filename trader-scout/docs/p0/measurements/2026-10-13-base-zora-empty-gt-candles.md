# Base Zora window check: verified swaps but empty GeckoTerminal candles

As of 2026-10-13, a bounded check of ten Base Zora candidates found a clear indexing gap: each exact-token GeckoTerminal pool-candle request returned HTTP 200 with zero rows, although each candidate has a verified V4 `Swap` after its recorded launch transaction. This is evidence of missing provider candles, not evidence of no trade or a zero price, and it does not establish an ATH.

The ten candidates are `0xe46504da7f7f9d9233d6118e27bdfbf27964a215`, `0x0c4235c9622cb3b8ca1320ef99d075030ef8a871`, `0x0344f696883be76e03a3859d91e6dca3cc26dbe8`, `0x0adc68afcf7bb72b6ac08adfa4eade6ad21a288b`, `0x087ea77ddf7ce82bec690482a80dc4f4631264d2`, `0x03e64387e109e519b0b6f96550fa8c4d1042be7d`, `0x048e4048a600a89a94bc50cfbadbaadb9cd4afe1`, `0x0941ed981b19931ed2ac9faae689fc795d4fc4a0`, `0x1019029751d2ac9faff00eb6ac3bb03a00265973`, and `0x07b29c826f5b71720c2e8d9738fa41fb78861225`. They were selected from the existing fixed-supply Zora boundary-price evidence; no holder gate was applied.

For each token, the requested pool ID is recorded in the immutable input manifest. The public v2 OHLCV request used daily candles (`aggregate=1`), USD, token-side `base`, `include_empty_intervals=false`, `limit=1000`, and `before_timestamp=1791676799`. All ten responses were HTTP 200 and contained zero candles. Requests were spaced at least 15 seconds apart, with no retries, no authentication, and no database writes. The full request parameters, exact response hashes, and raw responses are in `.scout-data/diagnostics/zora-gt-ten-price-completion-2026-10-13/manifest.json` and its `raw/` directory; the frozen candidate input is `input.json` (SHA-256 `fe795703735ad40699d093e25e2966b9a871581146f9627e35c5a9b0d039e759`).

I compared the ten recorded Swap transaction hashes with indexed Base `launches.tx_hash` values in a read-only, exact-address query: all ten hashes differed from their corresponding launch transaction hashes. For the nine candidates without a previously cached receipt/header, 18 bounded read-only RPC requests retrieved nine successful transaction receipts and nine block headers. Each receipt contained exactly one V4 PoolManager `Swap` log matching the candidate pool, transaction, and archived log index; its topics/data/address matched the archived full-range log response. All nine block hashes and timestamps matched the archived event. The already-cached e465 evidence was reused. Raw receipt/header bodies and SHA-256 values are under `.scout-data/diagnostics/zora-gt-ten-price-completion-2026-10-13/rpc-raw/`; the request accounting and checks are in `rpc-manifest.json` (18 requests, no retries, no DB writes).

This confirms actual post-launch swaps in the checked pools and rules out the explanation that these empty candle responses merely correspond to launch initialization. It does not prove the provider's candles are complete for other pools, and the single archived swap per candidate is not a historical price maximum. A numeric ATH/FDV still needs a dated USD price observation and complete-enough price scope under the existing source policy. No price was promoted from this check.

GeckoTerminal's public v2 network and OHLCV reference: <https://api.geckoterminal.com/docs/index.html>.
